# 自动压制：递归识别最深层素材目录

## 目标

自动压制扫描不再只认监控目录的**直接子文件夹**。改为任意深度识别「本层含视频」的目录作为剧目；若祖先目录也有视频，**只保留更深的一层**（祖先不单独成剧目）。剧目展示名使用相对监控目录的路径。

## 规则

- **成剧条件**：目录自身这一层存在视频文件（扩展名与现有一致）；视频列表仍只收集本层文件，不把子目录视频并入同一剧目。
- **优先更深**：某目录本层有视频 → 登记为剧目；继续扫描其子目录；祖先目录即使也有视频，也不因「路径包含关系」再登记祖先（实现上：只有「本层有视频」的节点入选，祖先若本层无视频本来就不会入选；若祖先本层也有视频，祖先与后代都会「本层有视频」——此时**仍登记后代**，并**丢弃**作为剧目的祖先，只保留更深节点）。
- **名称**：`name` = 相对监控根的路径，POSIX 风格 `/`（例：`儿子重病后…/en`）。`path` 仍为绝对路径，供 `auto-state` 与增量补压使用。
- **年龄**：`createdAtMs` 取该剧目目录自身创建时间（birth → ctime → mtime，与现逻辑一致）。
- **排除**（任意深度目录名）：`.` 开头、`影工输出`、`快压输出`、`_compressed`。
- **临时文件**：本层收集视频时继续跳过 `.` 开头（含 `.影工临时_*`）。
- **最大深度**：自监控根起最多 **8** 层，防止异常深树拖垮扫描。

## 实现边界

- 主要改动：`src-tauri/src/media.rs` 的 `list_drama_folders`（递归收集 + 祖先剔除）。
- 前端 `DramaFolder` 类型可不变；UI 已显示 `name`，会自然变成相对路径。
- 不改编码、原位替换、增量 `videoNames` 语义；旧记录仍按绝对 `path` 匹配。
- 监控根下直接有视频文件、无子目录：不把监控根本身登记为剧目（与现行为一致：只扫子树）。

## 验证

- 二级：`监控/剧A/*.mp4` → 一个剧目，name=`剧A`。
- 三级：`监控/剧A/en/*.mp4` → 剧目 name=`剧A/en`；`剧A` 本层无视频则不出现。
- 祖先本层也有视频：`监控/剧A/*.mp4` 且 `监控/剧A/en/*.mp4` → 只保留 `剧A/en`（及其它更深叶子），不保留 `剧A`。
- 排除名与临时文件行为保持。
- 单元测试覆盖相对路径命名与「丢弃有更深视频后代的祖先」。
