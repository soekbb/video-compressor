# 压制：按需转 H.264 / moov 后置，并设置默认分辨率

## 目标

压制前先判断片源，只在需要时动手：已是 H.264、已是目标分辨率、且 moov 后置则跳过；只差 moov 位置则流拷贝重排；否则重编码成 H.264，并用黑边对齐到设置中的 720p/1080p。压制与合成输出都不再使用 `+faststart`（moov 在文件尾）。

## 范围

- **改动**：压制决策与 FFmpeg 参数（`compress.rs` / `encode.rs`）、合成输出 flags 与分辨率不一致时的目标画幅（`media.rs`）、系统设置（`tasks.rs`、`settings.ts`、`SettingsView.vue`、类型）及对应测试
- **不改**：任务状态模型、取消键语义、画质档位（体积/画质）含义、合成在分辨率已一致时的策略顺序（FullCopy / VideoCopyAudioEncode / NormalizeThenCopy / FullReencode）

## 系统设置

新增两个独立字段，取值仅 `720` | `1080`，非法值回落 `1080`：

| 字段 | UI 文案 | 默认 |
|------|---------|------|
| `compress_resolution` | 压制默认分辨率 | 1080p |
| `merge_resolution` | 合成默认分辨率 | 1080p |

控件样式与现有「画质档位」切换按钮一致。保存后只影响**新任务**；进行中的任务沿用启动时读到的值。

画质档位说明里「分辨率均不变」改为指向这两项默认分辨率。

SQLite `settings` 表各加一列，`NOT NULL DEFAULT '1080'`，迁移方式与 `quality_preset` 相同。

## 目标画幅

短边口径，按片源（或合成时多数派）横竖选择画布：

| 档位 | 竖屏（高 > 宽） | 横屏（宽 ≥ 高） |
|------|-----------------|-----------------|
| 720p | 720×1280 | 1280×720 |
| 1080p | 1080×1920 | 1920×1080 |

比例不是 9:16 / 16:9 时：`scale` 到画布内完整可见，居中黑边补满，不裁切、不拉伸。小于目标也放大到画布（强制对齐）。

## 压制决策

探测：视频 codec、宽高、MP4 顶层 atom 顺序。`codec_name` 为 `h264` 视为 H.264。非 MP4、读不到 `moov`/`mdat`、或 atom 解析失败 → 视为不是 moov 后置。

`moov` 后置 = 顶层 atom 中 `moov` 出现在 `mdat` 之后。

| 条件 | 动作 |
|------|------|
| H.264 **且** 宽高已是目标画幅 **且** moov 后置 | **跳过**：原地压制不改文件；输出到其它目录则复制源文件 |
| H.264 **且** 宽高已是目标画幅 **且** moov 不在后 | **只重排**：`-c copy`，不加 `+faststart`，输出 MP4 moov 后置 |
| 其它（非 H.264，或宽高/画幅不符） | **重编码**：libx264（硬编回退链不变）+ 现有 AAC；`scale+pad` 到目标画幅；不加 `+faststart` |

横竖只看探测到的像素宽高（高>宽为竖），不单独解旋转矩阵。

只重排与重编码都显式 `-map 0:v:0 -map 0:a:0?`，不映射字幕/封面/数据轨，避免空流导致 mux 写不出文件。

输出分辨率校验对照**目标画幅**，不再要求与源宽高相同。复制到其它目录时覆盖已有目标文件（与现有 `-y` 一致）。

只重排失败 → 回退到重编码（同一目标画幅）。取消仍走现有 `cancel_key`。

自动压制增量逻辑不变：输出已有效则跳过；源文件已符合上表「跳过」条件时，原地任务视为完成、不重写。

## 合成

- 分集分辨率**已经一致**：不强制 720/1080，走现有快路径；输出去掉 `+faststart`，moov 后置。
- 分集分辨率**不一致**：用户确认「统一分辨率并开始」后，全部 `scale+pad` 到**合成默认分辨率**对应画幅，再 `FullReencode`。不再统一到第一集尺寸。
- 横竖：以各分集宽高计，多数派（高>宽为竖）；次数相同取第一集。
- 规范化单片（分辨率已一致、只修帧率）仍不 `scale`，只去掉 `+faststart`。

## 错误与回退

- atom 解析失败：按「不是 moov 后置」继续，不单独报错
- 只重排失败：回退重编码
- 重编码失败：现有硬编→x264 链，最后仍失败则任务失败
- 设置缺失/脏数据：分辨率当 1080p

## 测试

- 目标画幅：竖屏/横屏 × 720/1080 四格
- atom：`ftyp free mdat moov` → 后置；`ftyp moov mdat` → 前置；无 moov → 非后置
- 决策表：跳过 / 只重排 / 重编码 三种条件
- 设置：非法值 → 1080；迁移列默认 1080
- 合成：分辨率一致不改画幅；不一致时目标为设置档位+多数派横竖，而不是第一集尺寸
